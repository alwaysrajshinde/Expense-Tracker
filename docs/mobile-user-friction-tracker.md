# Mobile User Friction Tracker
**Application:** Personal Expense Tracker Mobile Edition  
**Tracking Period:** November 2026 Audit (v2.4.1)

| ID | User Journey Stage | Problem Observed | Severity | Root Cause | UX & Technical Improvement | Verification Status |
|---|---|---|---|---|---|---|
| **FRICTION-01** | First-Time Experience / Auth | Password placeholder said "At least 6 characters", but validation rejected passwords under 8 chars or missing numbers/symbols. | High | Validation rules in `AuthGate.jsx` required `>= 8` chars and symbols, but input placeholder was outdated. | Updated label to `Password (min 8 chars, with number/symbol)` and placeholder to `"At least 8 chars with number/symbol"`. | Verified (Build & Auth tests pass) |
| **FRICTION-02** | Budget Monitoring | Tapping the Monthly Budget on the Home Hero card did nothing when a budget was set. | Medium | Rendered as static `<p>` tag when `budget > 0`, forcing user to leave Home and navigate to More → Budget. | Converted to an interactive touch target with an `Edit` pill calling `onSetBudget` directly from Home. | Verified |
| **FRICTION-03** | Category Management | 12 category color swatches clipped and overflowed horizontally on 320px–360px phones. | Medium | Parent container had `flex items-center gap-1.5` without `flex-wrap`. | Added `flex-wrap items-center gap-2`, wrapping color swatches neatly within viewport width. | Verified |
| **FRICTION-04** | Expense Logging | Amount field hardcoded `₹` symbol even when the user changed currency to `$`, `€`, or `£` in settings. | Medium | Hardcoded `₹` text node inside `AddExpenseModal.jsx` instead of using the dynamic `settings.currency` prop. | Added `currency` prop to `AddExpenseModal` with fallback to `settings.currency || '₹'`. | Verified |
| **FRICTION-05** | Expense / Income Logging | Credit entries were called "Refund / Return", confusing users logging Freelance, Salary, or Cashback. Button still said "Save Expense". | High | Modal terminology was restricted to refunds; button text was static. | Renamed toggle to `Income / Refund`, dynamic title `Add/Edit Income / Refund`, and button `Save Income / Refund`. | Verified |
| **FRICTION-06** | Expense Logging | Logging an expense for yesterday required opening the native date picker and scrolling wheels. | Medium | Absence of quick relative date shortcuts in modal. | Added 1-tap `[ Today ]` and `[ Yesterday ]` pills above the date input for instant selection. | Verified |
| **FRICTION-07** | Transaction Management | Clearing multiple active filters (search + category + mode) required clearing 3 separate UI controls. | Medium | Absence of a composite filter reset action. | Added a prominent `Active filters applied` bar with 1-tap `Reset All Filters`. | Verified |
| **FRICTION-08** | Transaction Management | Delete confirmation dialog had no backdrop tap dismiss on mobile. | Low | Modal container lacked an overlay click handler. | Added `<div className="fixed inset-0" onClick={() => setDeleteConfirmId(null)} />`. | Verified |
| **FRICTION-09** | Home Dashboard | Tapping an item in "Recent Activity" on Home was inert. | Medium | Items were static rows with no tap-to-edit event handler. | Passed `onEditTransaction` prop and hooked tap handler with touch feedback (`active:scale-[0.99]`). | Verified |
| **FRICTION-10** | Reports & Analytics | Year selector bar in Yearly Report clipped on small screens (320px). | Low | Layout used rigid horizontal flex row without wrapping. | Converted to responsive `flex flex-col sm:flex-row gap-2.5` with `flex-wrap` pills. | Verified |
